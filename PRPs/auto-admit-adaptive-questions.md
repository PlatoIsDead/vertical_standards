# PRP: Авто-допуск к экзамену + адаптивное число вопросов

Заметки Дмитрия 31.08 (`data/meeting_notes/2026.08.31 Standards Vertical UI.txt`):

> «for the exam, it should be immediately allowed upon getting the passing
> grade from the test, not that it needs to be assigned by HR… the person
> should get identification that they can now do the exam»

> «How many questions does it make sense to make for this document? Then split
> it into a third for a test, and two thirds for an exam… we don't make 15
> questions for every uploaded file, because some files might be too small.»

## Goal

1. **Авто-допуск (а)** — решение юзера 31.08, две ветки по порогу базового:
   - **порог: 3 из 5 верных** (обобщение: `max(1, round(total * 0.6))` —
     для 5 вопросов = 3; та же формула при адаптивном числе);
   - **< порога = провал**: сообщение «не сдан (X/Y), перечитай документ и
     попробуй снова» → сессия назад в READING, кнопка [✅ Готов к тесту];
     при рестарте базового СБРОСИТЬ старые ответы фазы
     (`delete_session_answers(sid, "basic")`, score_basic=0 — иначе ловушка
     «_finish_phase считает ВСЕ строки фазы», см. _handle_retake);
   - **≥ порога = допуск**: сообщение «теперь можешь начать экзамен» +
     КНОПКА [🎓 Начать экзамен] — экзамен НЕ стартует сам. Новое состояние
     `EXAM_READY`: RAG/меню/документы свободны (как WAITING_HR), команды
     «Начать»/«Готов»/«Экзамен» → state EXAM + вопрос 1.
   HR получает уведомление-FYI (результат, без кнопки «Допустить»); команда
   «Допустить» остаётся рабочей для легаси-строк WAITING_HR.
2. **Адаптивное число вопросов (б)**: генератор сам решает, сколько вопросов
   осмысленно для документа (3–15 всего), делит ⅓ на базовый тест и ⅔ на
   экзамен. Все хардкоды 5/10/15 в HR-навигации, визарде и клавиатурах
   становятся динамическими от фактических длин.

## Why

- Живой тупик: сотрудник сдал базовый тест и ждёт HR, HR в отпуске → обучение
  стоит. Дмитрий явно попросил убрать блокировку (31.08).
- 15 вопросов к одностраничке = вода и мета-вопросы (жалоба на «пустые
  вопросы» уже была 17.08); большие документы 15 покрывают нормально.

### Адаптивные вопросы

Все хардкоды (grep 31.08):

- `app/course_generator.py`:
  - STAGE1-промпт (~26): «РОВНО 15 ключевых положений», facts_basic «ровно 5»,
    facts_exam «ровно 10» → **модель сначала выбирает N по объёму документа**.
  - STAGE2-промпт (~60): «итого ровно 5/10» → «по одному на каждое положение».
  - `_validate_facts` (~287): `len != 5/10` → диапазоны (basic 1–5, exam 2–10,
    exam == 2×basic НЕ требовать — только пропорция «примерно ⅓/⅔» промптом,
    валидатор проверяет невыход из диапазонов и exam >= basic).
  - Перегенерация одного вопроса (~246): `1 <= num <= 15` и сплит `num <= 5`
    → от фактических длин.
- `app/hr_tools.py::split_q_num/merge` (47–56): маппинг 1–5/6–15 → параметр
  `basic_len` (или считать от questions dict).
- `app/keyboards.py::hr_question_card` (252–268): `q_num < 15` (Далее),
  `q_num == 15` (danger-ряд) → параметр `total`.
- `app/bitrix_bot.py` 1269–1333: тексты «(6–15)», границы `1..15`, подписи

- Порог экзамена УЖЕ пропорционален: `_exam_pass_threshold` =
  `round(len(exam_questions) * 0.7)` — не трогать. Отчёты/xlsx считают от

- `questions_json` уже хранит списки — миграция БД не нужна; старые курсы
  с 5+10 продолжают работать (длины читаются из данных).

### Ловушки (из истории проекта)

- gpt-5.5: `max_completion_tokens`, БЕЗ temperature; пустой content =
  RuntimeError + retry ×2 бюджета (паттерн в `course_generator._llm`).
- Тестовые двойники `notify_hr`/`_send` без kwarg keyboard — kwarg передавать
  только при реальной клавиатуре (`**({"keyboard": kb} if kb else {})`).
- Инвариант клавиатур: payload = только команды FSM
  (tests/test_keyboard_design.py ALLOWED_PAYLOADS).
- Фоновые задачи в тестах: корутину звать `asyncio.run` напрямую (паттерн
  test_report_delivery).

## Implementation Tasks (по порядку)

1. **_finish_phase basic → порог + две ветки** (state_machine):
   `_basic_pass_threshold(questions) = max(1, round(len(basic) * 0.6))`.
   Провал: `update_session(state="READING", q_idx=0, score_basic=0)` +
   `delete_session_answers(sid, "basic")`; текст «❌ Базовый тест не сдан
   (X/Y, нужно {порог}). Перечитай документ и напиши *Готов* — попробуем
   ещё раз». Успех: `update_session(state="EXAM_READY", q_idx=0,
   score_basic=…)`; текст «🏁 Базовый тест сдан: X/Y!\n🎓 Ты допущен к
   экзамену ({M} вопросов, проходной {порог_экз}). Нажми кнопку или напиши
   *Начать*, когда будешь готов». Курс без exam_questions → сразу DONE
   (guard). notify_hr в обеих ветках FYI без кнопки «Допустить»
   («сдал → допущен автоматически» / «не сдал → пересдаёт базовый»).
   ВАЖНО: рестарт базового через «Готов» в READING должен чистить ответы
   фазы и на пути повторного входа (проверить `_handle_reading` «готов»).
2. **Состояние EXAM_READY**: новый `_handle_exam_ready` (клон
   _handle_waiting_hr; «начать/готов/экзамен» → EXAM + format_question(0));
   диспатч в process_message; `keyboards.for_session` раскладка;
   `_STATE_HINTS["EXAM_READY"]`; my_courses: EXAM_READY = «🎓 допущен к
   экзамену» (selectable); `_handle_course_switch` на EXAM_READY-строку →
   приглашение с кнопкой; bitrix_bot кортежи состояний (~868 и
   меню-блок). `admit_session` (легаси «Допустить») перевести на
   EXAM_READY — единый UX кнопки.
3. **course_generator адаптивный**: STAGE1 — первым полем ответа
   `question_budget` (int 3–15) с инструкцией «по объёму и насыщенности
   документа; маленькая инструкция = меньше вопросов; ⅓ базовых (округление
   вверх, мин 1), остальное экзамен»; факты по выбранному числу; валидаторы
   на диапазоны; STAGE2/критик — «по одному вопросу на положение».
4. **Динамическая навигация**: hr_tools.split/merge от basic_len;
   hr_question_card(course_id, q_num, total, basic_len — если нужен подписи);
   bitrix_bot карточки/визард/перегенерация — границы и «(N–M)» от длин
   курса; keyboards danger-ряд на q_num == total.
5. **Тесты**:
   - state_machine: базовый 2/5 → READING + ответы фазы стёрты, повторный
     проход с чистым счётом; 3/5 → EXAM_READY + текст допуска (экзамен НЕ
     начат); «Начать» в EXAM_READY → EXAM + вопрос 1; RAG/меню в EXAM_READY

     легаси WAITING_HR + «Допустить» → EXAM_READY (адаптировать тест).

     (test_state_machine, test_buttons_everywhere::
     test_finish_basic_admit_button_env_gated — теперь клавиатуры «Допустить»
     НЕТ), напоминания.
   - generator: фикстуры с question_budget 6 (2+4) и 15 (5+10); границы
     перегенерации; hr_tools сплит при basic_len=2.
   - keyboard_design: card-сэмплы с total≠15.
6. **Прогон**: `ruff check . && python -m pytest tests/ -q` → 0 фейлов.
7. **Деплой**: commit → push → ./deploy.sh. Старые курсы (5+10) живут без

## Осознанные допущения (сказать юзеру при сдаче)

- Порог базового обобщён как 60% (`max(1, round(0.6 * total))`) — даёт
  ровно «3 из 5»; при адаптивном числе вопросов масштабируется.
- Число пересдач базового не ограничено (лимит не оговаривался).
- WAITING_HR-код не удаляется — легаси-строки в проде; «Допустить» теперь
  ведёт в EXAM_READY (кнопка), а не сразу в EXAM.
