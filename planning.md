## Что такое этот проект

Корпоративная система обучения сотрудников апарт-отелей «Вертикаль» на базе Bitrix24.
HR загружает документы со стандартами → ИИ генерирует курс → сотрудник проходит обучение через чат-бота.

Клиент: отели «Вертикаль» (+ возможно франшизы и Becar).
Референс: Marriott Digital Learning Zone (Axonify) — ориентир, не цель.

---

## Текущая архитектура — 3 потока

### Поток 1 — новый документ
```
Bitrix Disk → поллинг каждые 5 мин → скачать файл (docx/md) →
чанкинг → embeddings (text-embedding-3-small) →
GPT генерирует 5+10 вопросов → черновик в SQLite + JSON →
HR получает уведомление в чате
```

### Поток 2 — проверка HR
```
HR пишет боту команду →
  Курсы         — список черновиков
  Вопросы {N}   — просмотр вопросов
  Подтвердить {N} — активировать курс
  Допустить {X} — допустить сотрудника к экзамену
```

### Поток 3 — обучение сотрудника
```
READING → BASIC_TEST (5 вопросов) → WAITING_HR → EXAM (10 вопросов) → DONE
```
- В READING: сотрудник получает ссылку на документ, может задавать вопросы через RAG
- WAITING_HR: заблокирован до команды HR `Допустить`
- Результаты сохраняются в SQLite после каждого шага

## Что обсуждали

### ТЗ vs текущая реализация
Исходное ТЗ описывало полноценный веб-портал (FastAPI + React) с:
- Защитой от копирования (водяные знаки, блокировка Ctrl+C)
- Ролевой моделью с SSO
- Эскалацией стандартов
- Журналом аудита

**Решение:** отказались от отдельного веб-портала, всё через Bitrix24 чат-бота.
Bitrix закрывает: хранение файлов, ролевая модель, уведомления, задачи.
Bitrix не закрывает: защита от копирования, DRM, AI-обучение — это внешний сервис (наш бот).

### Marriott DLZ
Ориентир для direction, не конкурент. Их стек (Axonify) стоит миллионы.
Наш подход: те же ключевые функции (обучение + тест + допуск) через знакомый интерфейс (чат).
Преимущество: не нужен отдельный фронтенд, работает на мобильном.

### RAG-баг (пожар)
Запрос «Что делать при пожаре» вернул раздел для **гостей** вместо раздела для **персонала**.
Причина: все чанки в одном индексе без метадаты аудитории, `section_filter=None`.
Фикс: добавить поле `audience` (staff/guest) при чанкинге, фильтровать в RAG.
Статус: **✅ закрыт в доработке №1 (июль 2026)** — `audience` в чанках, guest-чанки
никогда не отдаются; живой eval 6/6 (`scripts/eval_roles.py`).

### Bitrix webhook OnDiskFileAdd
Событие не найдено в документации (51k строк bitrix24_docs.md).
Вероятно доступно только через OAuth-приложение (event.bind), не через простой вебхук.
Поллинг каждые 5 минут — основной механизм до выяснения.

### Streamlit
**Отказались полностью.** Всё управление через команды в чате.

### Модель
Вопрос о переходе с OpenAI на Claude — **отложено**.

Заметки по №1:
